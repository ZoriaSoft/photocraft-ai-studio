# Repository cleanup policy

PhotoCraft AI Studio intentionally keeps the mature editor engine from upstream while product-specific AI features live above it. Cleanup should reduce fork-only noise without making upstream synchronization unnecessarily difficult.

## Keep: product foundations

These are used directly by the desktop editor or by AI Studio workflows and should remain in the repository:

- `crates/engine`, `doc`, `io`, `format`, `codecs`, `psd`, `compose`, `ops`, `raster`, `color`, `cms`
- `crates/ui-egui`, `gpu`, `paint`, `algo`, `text`, `vector`, `tablet`
- `crates/automation`: the desktop app and control layer depend on it; AI and batch workflows also benefit from the deterministic command surface
- `apps/photocraft`: primary desktop product
- tests, scorecards, performance budgets and release tooling that protect upstream compatibility

## Keep for now: optional surfaces

- `apps/photocraft-cli`: useful for automation, regression testing and future headless AI workflows
- `apps/photocraft-web`: not part of the first desktop AI Studio MVP, but it is small and keeping it avoids unnecessary workspace/upstream divergence for now
- `book/` and upstream technical docs: still document engine behavior that AI Studio inherits

These can be removed later if the product direction explicitly becomes desktop-only and the maintenance cost outweighs upstream-sync value.

## Remove now: obsolete fork presentation assets

The fork should not ship stale upstream marketing screenshots that are no longer referenced by its README or product documentation. The documentation surface now uses reproducible AI Studio screenshots generated by `crates/ui-egui/examples/snapshot.rs`.

Also remove isolated screenshots with no references anywhere in the repository. Trademark terms are retained even though upstream ArtCraft logo/mark image assets are not distributed.

## Rule for future cleanup

Before removing a crate or feature, verify both Cargo dependency reachability and runtime/UI references. Prefer hiding or feature-gating optional capabilities before deleting engine code. This keeps AI Studio focused without turning every upstream update into a large manual port.
